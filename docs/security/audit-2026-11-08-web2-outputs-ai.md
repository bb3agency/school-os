## Verified clean (no finding)

- **Ask stream** (`sse.ts`, `answer.ts`, `chat.tsx`): SSE parser handles CR/LF/CRLF splits across chunks;
  every event is zod-checked and malformed or unknown events are ignored; `final` replaces the preview
  and later `token`/`delta` are ignored; Stop aborts the fetch and cancels the reader; a failed request
  un-supersedes a regenerated answer; a cut-off stream stays live with Retry. Status comes from `done`
  (source of truth); "not found in school records" when no citations and no status (older API).
- **Citations**: `[n]` becomes a chip only for an index that came in a `citation` event; source URIs are
  parsed by strict regexes (UUIDs, page numbers) and unknown `sos://` kinds go through
  `GET /knowledge/resolve` with an app-relative-path check; withheld answers hide text and follow-ups.
- **No prompt/answer text in logs or analytics**: no `console.*`, `sendBeacon`, `localStorage` or
  `sessionStorage` use in any feature of this area; presigned URLs are opened once and never stored.
- **Usage/quota** (`usage.ts`): numbers only for `tenant.billing.read` (API sends null otherwise);
  `included_answers` is `ge=1` in the API, so `usedPercent` cannot divide by zero.
- **Documents**: upload checks type/size before sending, posts straight to storage with progress, renews
  both keys after a storage failure; list and detail poll while a version is scanning and stop on error;
  download only for `ready` versions and only for members who may open C3 files; quarantined/failed
  versions explain why and offer no download.
- **Exports**: the "whole school" view is never asked for without `export.read_all`; downloads are shown
  from the server's `can_download`; step-up note for someone else's export, student lists and restricted
  columns; stale codes reload the export; print-job PDFs keep their key on retry (WD-07).
- **Certificates**: approve/reject/withdraw/duplicate/cancel only from the server's `can_*` flags, with
  If-Match (and `draft_sha256` on approve); duplicates carry an Idempotency-Key; the register "Prepare"
  check (`check=true`) is not audited and the print view link is the one audited view.
- **Circulars and notices**: suggestion confirm/dismiss, review, notice edit/approve/draft retry/render
  all use If-Match; IST "today" for due states; the WhatsApp text is English only while Telugu is off.
- **Notifications**: bell polling backs off on failures, stops on 401/403 and in hidden tabs, and is
  marked passive (does not reset the idle timer); every `resource_type` has a screen (WF-01 guard).

## Outside my area (reported, not changed)

- `features/fees/ReceiptDetailScreen.tsx`: a receipt whose `pdf_status` is `queued` is not read again
  either (same class as XO-03); the fees auditor may want to add the same polling.
- `lib/bff/query.ts` `toLoadable`: any `isError` (also a failed background refetch or poll while data is
  shown) turns a `DataTableV2` into its error state and hides the rows. XO-05 fixed the next-page case in
  my screens only; a shared rule ("keep data, show the error beside it") would need an owner decision.
