# Security audit 2026-10-04: web, AI and infra

Auditor 3 of the wave-4 deep audit, on branch `wip/sec-web-ai-infra` from
`claude/friendly-ptolemy-0tl3br` at 3d408fc. Scope: the Next.js BFF and browser, the AI pipeline
(`app/knowledge`), config guards, Terraform, `deploy/dedicated`, GitHub Actions and the
dependency and secret scans. The baseline is CLAUDE.md §6 and §11, docs/07 and docs/08.

Every finding below has a concrete path from input to code to outcome. Each fixed finding has a test
that failed before the fix and passes after it.

## Hardening notes (no exploit path found)

- **BFF `active-tenant`** (`apps/web/src/server/auth/handlers.ts:696-724`): the session stores the chosen school unless the API answers 401, 403 or a 5xx other than 501. A 404, 422 or 429 still sets it. The API re-checks membership on every request, so this gives no access. Recommendation: store it only on a 2xx. **Fixed in c83ee23e.** The school is stored only on a 2xx. Test: web `apps/web/src/server/auth/handlers.test.ts` "stores the school only on a 2xx".
- **`apps/web/src/server/session/crypto.ts:58`**: AES-GCM without `authTagLength`. This is not exploitable, because `unseal` always slices exactly 16 tag bytes. Passing `{ authTagLength: 16 }` would silence semgrep `gcm-no-tag-length`. Already fixed in 40f3798a.
- **`apps/api/app/identity/tokens.py:509`**: `jwt.decode(verify_signature=False)` only picks the verifier, which checks the signature and issuer again. It is a semgrep true positive by pattern but safe by design. **Fixed in fcd0ca06.** A test pins that the unverified `iss` never replaces the signature checks: `tests/identity/test_support_tokens.py::test_SEC_002_*`.
- **`migrator_database_url`** is not covered by the `dev-only` staging/prod check. I did not add it, because the api containers in prod do not set it (only the migrate task does), so the guard would stop the api from starting. Recommendation: guard it in the migrate entrypoint. **Fixed in b6951402** (merged in 32029d64, wip/ob-ci-dedicated). The migrate entrypoint refuses the dev-only migrator URL in staging and prod. Tests: `tests/deploy/test_dedicated_hardening.py::test_hardening_migrate_refuses_the_dev_only_migrator_url`, `::test_hardening_migrate_entrypoints_use_the_checked_url`.
- **`SOS_ENV` defaults to `local`**, which turns every staging/prod guard off. It is set in every deployment and asserted in `shared_platform.tftest.hcl`. Consider `ENV SOS_ENV=prod` in the image. **Fixed in b6951402** (merged in 32029d64). The Python image defaults to `SOS_ENV=prod`; local compose and CI set it explicitly. Test: `tests/deploy/test_dedicated_hardening.py::test_hardening_python_image_defaults_to_prod`.
- **Dedicated compose** pins the caddy, pgvector and valkey images by tag, not digest; the API Dockerfile base is also tag-only. `upgrade.sh` is called without `--sha256`, so the checksum comes from the same S3 prefix as the bundle. **Fixed in b6951402 and 66baf982** (merged in 32029d64). The caddy, pgvector, valkey and API base images are pinned by digest. The fleet deploy passes the GitHub release's SHA-256 to `upgrade.sh --sha256`. Tests: `tests/deploy/test_dedicated_hardening.py::test_hardening_third_party_images_are_pinned_by_digest`, `::test_hardening_api_base_image_is_pinned_by_digest`; `tests/deploy/test_supply_chain.py::test_P2_08_fleet_deploy_passes_a_checksum_from_the_github_release`.
- **Caddy** (`deploy/dedicated/Caddyfile:10`): `trusted_proxies static private_ranges`. Neither the API nor the BFF reads X-Forwarded-For, so this affects only Caddy's logs. **Fixed in b6951402** (merged in 32029d64). Caddy trusts no forwarded headers. Test: `tests/deploy/test_dedicated_hardening.py::test_hardening_caddy_trusts_no_forwarded_headers`.
- **Knowledge**: `/knowledge/search` has no per-user rate limit, and the Voyage embedding and rerank calls are not metered against the budget. The contextualize prompt does not escape `</document>`; its output is used only for ranking and is never cited.
  - Search rate limit: **Fixed in ab4f0339.** Test: `tests/core/test_ratelimit.py::test_SEC_020_*`.
  - Contextualize escape: **Fixed in 3136ae22.** Test: `tests/knowledge/test_contextual.py::test_SEC_020_*`.
  - Voyage metering: **Left open:** no embedding model or price is chosen yet (ADR-0006).
- **Web XSS surface checked and clean**:
  - There is no `dangerouslySetInnerHTML` anywhere.
  - Answer markdown is an in-house parser that renders only React text nodes; links appear only for validated `sos://` sources, mapped to app paths, and `javascript:` never becomes an `href`.
  - Citations, the popover, sheet grid cells, notification titles and bodies (links only from UUID `resource_id` through a fixed map), announcements and support ticket threads all render as text.
  - The print and memo HTML from the API is escaped and served under a strict hash-only CSP, which `isStrictPolicy` re-checks.
- **BFF checked and clean**:
  - Traversal is blocked: `%2f`, `%5c`, `%2e`, backslash and dot segments are refused, and the edge and platform checks run on the decoded path.
  - Absolute URLs cannot be built: the path must start with `/api/v1/` and the base is `API_INTERNAL_URL`.
  - The Host header is never used (`APP_BASE_URL` only).
  - Request and response headers are forwarded from allowlists, and Location is rewritten or dropped.
  - Tokens never reach the browser or logs, and the log fields are allowlisted.
  - CSRF uses a synchronizer token with Origin and Sec-Fetch-Site checks.
  - `safeNext` covers open redirects, including `//`, backslash, control characters, legacy-locale `/en//x`, the BFF itself and kind-crossing.
  - A new session id is issued at every sign-in and step-up.
  - Clickjacking is blocked by `frame-ancestors 'none'`.
  - The CSP uses nonce plus `strict-dynamic` with no inline styles in production. Motion animates through the CSSOM (style properties), which CSP does not block.
