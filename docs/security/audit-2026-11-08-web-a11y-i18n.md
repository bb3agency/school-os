# Audit 2026-11-08: web accessibility (WCAG 2.2 AA) and language/formatting

Web accessibility and i18n auditor of the 2026-11-08 frontend wave, on worktree branch
`worktree-agent-a5c1920719e257298` from `main` at `813c3996`. Scope: `apps/web` school console,
operator console and parent/public pages: accessible names, focus, keyboard, target size, live
regions, form labels, headings, tables, contrast, reduced motion; i18n key parity, interpolation,
plurals, Indian number/currency/date formatting, and the English-only rule while
`SOS_TELUGU_ENABLED` is off (ADR-0036). Items fixed by the 2026-10-17 web audit (WEB-01..16)
were not re-reported.

Each fixed finding has a test that failed before the fix.

## Method

- **axe-core 4.14 over the whole unit suite.** A temporary `afterEach` hook in
  `vitest.setup.ts` (not committed) ran axe on `document.body` after every one of the 2,323
  vitest tests (populated screens from the feature tests and the 404/empty state of every page
  in `english-only.test.tsx`), with `color-contrast`, `target-size` and `region` off (no layout
  in jsdom). Result: no WCAG A/AA rule violation (labels, names, ARIA, lists, tables, `lang`,
  duplicate ids). Only best-practice rules fired: `heading-order` (WA-02), `landmark-unique`
  (WA-03) and duplicate-landmark noise from tests that render two pages in one test.
- **`label-content-name-mismatch` cannot be checked in jsdom**: a probe showed axe returns it
  as *incomplete* (it needs rendered visibility). It was therefore checked statically: every
  `aria-label={t("…")}` on an element whose child is `{t("…")}`, compared in en and te, plus
  every template-string `aria-label` and every `label` prop that becomes an `aria-label` on a
  trigger with visible content (`Menu`, `Popover`, `IconButton`).
- **Static i18n scan** of every `t("key", {…})` call bound to `useTranslations`/
  `getTranslations("ns")`: key exists in `en.json`, resolves to a message (not an object), and
  the call passes every ICU argument the message uses.

## Verified clean

- **Accessible names (2.5.3)**, statically: all other buttons/links with an `aria-label` and
  visible text contain the visible text in en and te (`invitations.accept/decline`,
  `ask.memory.confirm/dismiss`, Tally `link`, invoice and template downloads, task moves,
  citation links, audit "filter by user", dev sign-in). `Menu` drops its `aria-label` for text
  triggers; the table column `Popover` passes no label.
- **i18n calls**: no `t()` call with a missing key, an object key, or a missing ICU argument
  (the scanner's six hits were plural branch words such as `=0 {Blockers}`). en/te key, ICU
  argument and branch parity are already enforced by `i18n/messages.test.ts`; renders log
  next-intl errors into `intlErrors`.
- **Formatting**: money goes through `lib/format.ts` `formatInr` (`en-IN`, `INR`, Latin digits:
  `₹1,23,456.00`) or the parent-page formatter with the same grouping; dates through
  `lib/date-format.ts` (school format, DD/MM/YYYY default, `Asia/Kolkata`); parent pages use
  `parentDate` (DD/MM/YYYY, IST). Month labels use UTC on date-only values (no day shift).
- **English only (ADR-0036)**: every Telugu field (`summary_te`, `title_te`/`body_te`,
  `label_te`, `display_te`, letterhead `_te`) is shown or edited only behind `useTeluguEnabled()`
  or `locale === "te"`; parent pages use the parent language the API sends by design
  (`server/public/messages.ts`, ADR-0044).
- **Forms**: `Input`/`Select`/`TextField` wire `label for`, `aria-describedby` (hint, error) and
  `aria-invalid`; `ErrorSummary` takes focus and links to fields; axe `label` rule clean in all
  tested states.
- **Contrast**: `components/ui/tokens.test.ts` checks 90+ token pairs from `globals.css`
  (single light theme; no dark theme ships). **Reduced motion**: `MotionProvider`, dialogs,
  menus, toasts, Ask motion and Lenis honour `prefers-reduced-motion` (`motion-states.test.tsx`).
- **Dialogs**: native `<dialog>` with focus return; drawer focuses its close button and returns
  focus to the menu button.

## Outside my area / notes

- `english-only.test.tsx` page `ask/verified` timed out (60 s) once while the temporary axe hook
  ran on every test; without the hook it passes (load-dependent, not a product bug).
- `features/ask/ChatScreen.tsx:369` picks the greeting from the device clock
  (`new Date().getHours()`), not IST; harmless on office PCs set to IST, so not a finding.
- Target size (24 px, 44 px coarse) and contrast in rendered pixels need a browser: covered by
  `e2e/a11y.spec.ts` and `e2e/responsive.spec.ts` (not run here, per the brief).
