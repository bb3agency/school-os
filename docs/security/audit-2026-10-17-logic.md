# Audit 2026-10-17: backend business logic, data integrity and concurrency (logic)

Branch `wip/audit-logic` from `main` (aaa6e0fd). Scope: the backend modules' business rules, data
integrity, concurrency, time zones (IST against UTC), money rounding and job reliability, with
the newest R1 features first (APAAR consent register, PEN guard, readiness, boards, print jobs;
ADR-0039, ADR-0040, ADR-0041). Security and isolation, and frontend, UX and docs, were audited
separately and are out of scope here.

**Method.** Each finding below has a test that failed before the fix and passes after it. Where
there is no fix, the finding is reported with the owner decision it needs. Data is synthetic only.
Paths are relative to `apps/api/`.

## Checked and not a bug (false positives)

- **Certificate serial numbers.** These stay gap-free under concurrency. `allocate_serial` is an `INSERT … ON CONFLICT DO UPDATE` on the counter row, which locks it until commit. Every later failure rolls back the same transaction, number included.
- **Change requests.** `approve` locks the student before it compares `old_value_id`, so there is no TOCTOU. Self-approval, expiry, If-Match and requester status are all checked.
- **Imports.**
  - Duplicate PEN or APAAR ID rows within a file are row errors. Validation and the existing-holder lookup clean values the same way (`cell_text`, then spaces and hyphens removed).
  - A clash that appears between validation and commit aborts the commit, all or nothing.
  - The revert plan refuses when a batch value was superseded.
- **DQ engine.** Concurrent runs lock findings in id order, and inserts use `ON CONFLICT DO NOTHING` on the fingerprint. A refusal clears findings as `auto_cleared`, not `needs_confirmation`, because no compared value changed.
- **Readiness diff (pure).** NFC first. Day/month swap needs a different date. The undecided and corroborated referee paths behave as documented.
- **Idempotency keys.** These are claimed with an insert in the request transaction; a concurrent duplicate waits on the unique key.
- **IST boundaries.**
  - AI budget months (`budget_month`) and usage-collector days are IST.
  - Invoice generation (02:00 IST) runs after usage collection (01:30 IST), so last month's overage is complete.
  - Certificates, academics, circulars, insights and imports use IST dates.
- **GST.** Tax is computed per rate group on rounded line amounts, CGST and SGST are halves rounded to paise, and the negative total is refused.
- **Tally duplicate parties under concurrent syncs.** These are prevented by the unique keys `(tenant, company, guid)` and `(tenant, company, ledger_name) WHERE guid IS NULL`.

Both permissions therefore apply, as FR-DQ-046 asks. Its docstring now says so (8be168d5).
