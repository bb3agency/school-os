## Procedure

1. Source: throwaway container, `infra/db/bootstrap.sql`, `alembic upgrade head` as `sos_migrator`, audit partitions (as `make migrate`).
2. Seed synthetic schools through the module services, run the data-quality checks, verify every audit chain, record exact per-table row counts (as `postgres`).
3. Backup as `backup.sh`: `pg_dump -U postgres -d schoolos -Fc -Z 6` inside the container, `pg_restore --list` on the file, SHA-256.
4. Target: a second throwaway container bootstrapped like a fresh host (bootstrap.sql creates the roles; a dump carries no roles).
5. Restore as `restore.sh` (drill path): checksum, `CREATE DATABASE … TEMPLATE template0`, `pg_restore --exit-on-error`, `ANALYZE`.
6. Verify the copy (checks below).

## Findings from this drill (added by hand)

1. **`restore.sh` verified the platform chain of the live database.** The drill step ran
   `python -m app.audit.verify_all` with only `SOS_DATABASE_URL` pointed at the scratch copy, so
   `verify_platform` used `SOS_PLATFORM_DATABASE_URL` from the stack (database `schoolos`).
   Fixed: the script now passes `SOS_PLATFORM_DATABASE_URL` for the copy too
   (`apps/api/tests/deploy/test_restore_script.py`).
2. **`restore.sh` summary skipped the `fin` and `msg` schemas** (35 tables, including the fee
   ledger and receipts) in its table and row counts. Fixed: the schema list now matches
   `infra/db/bootstrap.sql` (same test).
3. Coverage gap, not a defect: the synthetic seeder does not create fee or messaging rows yet,
   so `fin.*` and `msg.*` were restored and RLS-checked but empty. Files (S3) are out of scope
   for a database drill.
4. The `Commit` above is the base commit; the drill code itself was in the working tree of the
   branch that adds it.
